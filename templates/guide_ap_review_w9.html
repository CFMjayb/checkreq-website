Coding, correcting and posting requests — and handling vendor W-9s.

← Back to {{ guide.back_label }}

The AP Review screen

  • Needs GL Coding — requests submitted with “Ask My Accountant.” Click Open & Code, add the GL line(s), then Save & Start Approval. If the submitter is also the approver, it goes straight to Approved.
  • Pending — fully approved requests. Tick several and use Post Selected to QBO, or post one at a time. Posting creates the Bill in QuickBooks with the documents attached.
  • A red ! beside a request number means the last post to QuickBooks did not go through, or QuickBooks already has that invoice number for the vendor. Hover over it for the full message. What to do.
  • Click any request number to open the edit screen.

When a post does not go through

Beacon asks QuickBooks before it creates a Bill whether that vendor already has a Bill under the same number, because QuickBooks refuses a second one. A request that fails, or that QuickBooks already holds, stays in Pending with a red row, a red ! and the reason — it is never lost, and nothing is created in QuickBooks. Every failed attempt is also written to the request’s history.

Already in QuickBooks

The row names the Bill QuickBooks holds (its amount, date and whether it is paid). Try QBO Post again and the checkbox stay off while QuickBooks still has that number. If this is a different invoice that reuses the number, open the request (Edit) and change the invoice #. If it is the same invoice that was already entered, use Cancel CR.

Any other failure

For example QuickBooks was unavailable. The row shows when it failed and why. Try QBO Post again sends it again (and you can still tick it for Post Selected to QBO).

Cancel CR

Asks for a reason, then takes the request out of AP Review for good. The request is kept — its history shows who cancelled it and why — but it can no longer be posted. Only a request not yet posted to QuickBooks can be cancelled here.

Correcting a request

The edit screen shows the whole request with the invoice beside it. AP Reviewers, CFOs and Beacon Admins can change the vendor, amount, GL coding, program area, pay date, description and attachments on any request until it is posted. Saving never restarts approval; every change is recorded in the request’s history with what it was before and after, and the check request PDF that goes to QuickBooks is regenerated.

Vendor W-9s

A request is held when the vendor’s payments this year pass the W-9 threshold and no W-9 is on file. The W-9 section of the edit screen shows where it stands:

On hold / waiting

Send W-9 Request emails the vendor a secure upload link (good for 7 days; Resend renews it). Or release the hold: never needs a W-9 (e.g. a corporation — applies to all its requests) or post this request without a W-9. Both need a reason.

Take action on received W-9

The vendor uploaded it; it opens in the viewer. Type the EIN or SSN from the form, tick 1099 unless the vendor is a corporation, then Confirm W-9 and update QuickBooks. If the form is wrong, use request a corrected one.

On file

Confirming sends the tax ID and 1099 setting to the QuickBooks vendor, attaches the W-9 to it, and releases the hold on every request for that vendor. Beacon never stores the tax ID.

The 7 AM email

Each morning, AP Reviewers get one email — only when something is waiting at their entities — listing requests to code, W-9s to review, requests ready to post, and requests on hold. Each item links straight to the request.
